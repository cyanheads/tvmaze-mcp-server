# 0.2.1 — 2026-10-08

## Changed

- **Tool arguments are repaired before validation** (`@cyanheads/mcp-ts-core` 0.13.14, [#707](https://github.com/cyanheads/mcp-ts-core/issues/707), [#616](https://github.com/cyanheads/mcp-ts-core/issues/616), [#570](https://github.com/cyanheads/mcp-ts-core/issues/570)) — a string spelling a number or boolean (`show_id: "82"`, `include_specials: "true"`) becomes the number or boolean, and `null` at an optional key is treated as absent. Repairs reach the variants of `tvmaze_get_cast` (`scope`), `tvmaze_get_next_episode` (`by`), and `tvmaze_lookup_show` (`source`). A `-32602` argument rejection is bounded in size (0.13.14, [#648](https://github.com/cyanheads/mcp-ts-core/issues/648)).
- **An integer sent for a string field becomes its digits, and argument-rejection hints keep each field's path** (0.13.9, [#487](https://github.com/cyanheads/mcp-ts-core/issues/487), [#493](https://github.com/cyanheads/mcp-ts-core/issues/493)).
- **Tool error results carry `data.requestId`**, and their text ends with `request <id>` (0.13.10, [#576](https://github.com/cyanheads/mcp-ts-core/issues/576)).
- **MCP SDK 2.1 over HTTP** (0.13.9) — a 2026-07-28 POST without `MCP-Protocol-Version` is refused `400` / `-32020`, and a JSON-RPC batch over 100 messages is refused.
- **`ctx.recoveryFor(...)` spreads dropped from the handlers and the service** — the framework fills each declared recovery hint from the throw's `reason`. No change to what callers receive.
- **`server.json` npm entries** drop the `run start:*` package arguments and set `runtimeHint: "npx"`; the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `http` (adopted from the 0.13.11 scaffold fix, [#622](https://github.com/cyanheads/mcp-ts-core/issues/622)).
- **Docker image** (0.13.10 [#575](https://github.com/cyanheads/mcp-ts-core/issues/575), 0.13.11 [#608](https://github.com/cyanheads/mcp-ts-core/issues/608)) — production dependencies install in a `deps` stage on the build platform, OTel peers install at the framework's declared ranges via `scripts/install-otel.ts`, and musl-only packages are pruned by `scripts/prune-musl-packages.ts`. Base images Bun 1.4.0 → 1.4.2; `MCP_FORCE_CONSOLE_LOGGING` removed (nothing read it).
- **`.env.example` documents** `MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, and the per-signal OTLP endpoints; the README configuration table gains a `LOG_TOOL_FAILURE_PAYLOADS` row and the MCP SDK badge reads `^2.2.0`.
- **Ignore files and packaging** — `.gitignore` and `.dockerignore` cover every `.env*` file except the templates; `.mcpbignore` excludes `logs/`, `.cache/`, `coverage/`, `tests/`, and `docs/idea.md`; `package.json` `files` gains `!dist/*.mcpb`; `packageManager` is `bun@1.4.2`.
- **CodeQL** runs one job per language (`actions`, `javascript-typescript`), each uploading under its `/language:<language>` category.
- **Tooling scripts and skills synced to the 0.13.14 templates** — `devcheck`, `lint:mcp`, `lint:packaging`, skill-version and anti-pattern checks, `release:github`, `framework-skills/`, and the CLAUDE.md / AGENTS.md agent protocol.
